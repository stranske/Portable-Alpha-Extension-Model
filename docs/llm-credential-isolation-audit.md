## Guard and coverage limits

`tests/test_dashboard_llm_settings.py::_credential_boundary_findings` inventories explicit API-key-key assignments and raw named provider-exception logger sinks in these five concrete paths. The sole exact existing exception is Config Chat's private unscoped key read, tied to the reproduced finding above; a new path/assignment or raw provider error log fails the guard. Negative controls cover a run-only key and both raw exception/traceback logs. This small AST guard cannot detect arbitrary aliases, indirect logging or data flowing through third-party SDKs. Offline behavior tests cover the actual known paths independently.

The Explain scope-specific regression lives in the acceptance-criteria-named test file. Temporarily removing the real saved-provider override write must make its widget-cleanup behavior fail, then byte-identical restoration returns green. The settings guard also fails when an actual Explain key loses provider binding or the comparison provider handler logs its raw exception. These are proof targets, not permanent production changes.

## Unpublished follow-up proposals for review

A. **Config Chat private override identity** (confirmed function-level reproduction). Bind `_CONFIG_CHAT_API_KEY_KEY` to selected provider or explicitly discard it on provider change, then replace the characterization with a correct-isolation regression. First establish how a supported user flow populates that private slot. Scope excludes Results panels, credential rotation and provider changes. Related existing owner #2366; no additional issue is filed without separate approval.

B. **Telemetry exception/extra boundary** (needs-investigation). Inject synthetic markers through fleet failure exceptions and extra metadata; inspect actual local record/log output with no remote tracing. Only a reproduced unresolved exposure warrants a proposed instance. Do not infer exposure solely from `exc_info=True`, or infer safety from SecretStr/hashes.
